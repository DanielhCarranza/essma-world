# Essma World Roadmap

The roadmap prioritizes a delightful, safe first play session over broad but shallow content. Dates are intentionally omitted until the team establishes capacity, art throughput, and playtest cadence.

## 0. Pre-production

**Deliverables:** canonical cast sheet; approved visual system; content/safety review process; catalog IDs and layering rules; clickable screen flow; technical spike plan; first asset briefs.

**Exit gate:** all documents in this package are approved, the starting ten items have briefs, and the team can name the source/provenance for every planned asset.

## 1. Playable Core

**Deliverables:** Mexican-Spanish illustrated map; persistent Phaser ranch; Essma, Juancito, Tori, and Anita dress-up; twenty starter wearables; ten patio decorations; settings; IndexedDB save; guarded caregiver export/import; touch, mouse, and keyboard support.

**Dependencies:** base-character layers, UI kit, save schema, scene-loading strategy, and child playtest script.

**Exit gate:** a child can independently enter the ranch, create a look, place a patio object, reopen the game, and see both choices. No account, payment, ad, chat, analytics, or external-link path exists.

## 2. Cozy Ranch Expansion

**Deliverables:** animal care; one short visual quest; expanded collection/unlock feedback; photo mode; and one optional mini-game with a declared learning intent.

**Dependencies:** layout schema migration, furniture catalog, undo/reset controls, reward validation, and cultural/content review.

**Exit gate:** a player can complete a short optional activity, receive an approved reward, place/remove it safely, and retain progress without a punitive timer or paid shortcut.

## 3. World Expansion

**Deliverables:** turn one of the five locked map places into a playable second region, then add desert/pueblo/oasis stories, collectibles, shops without real-money purchasing, a festival framework, and reviewed new NPCs/companions.

**Dependencies:** region content budgets, travel/loading design, localization review, and performance testing on target devices.

**Exit gate:** each new region has a distinct play reason, a small self-contained asset pack, clear return navigation, and accessible text/audio behavior.

## 4. Future Modules

**Deliverables:** Essma Bros adapter after source review; additional mini-games; optional isolated 3D prototype; seasonal content tools; an evaluated parent-controlled cloud-backup option.

**Dependencies:** mini-game contract compliance, security/privacy review for any cloud work, 3D performance budget, and controlled rollout plan.

**Exit gate:** no module can corrupt the core profile, bypass reward validation, introduce unreviewed child data collection, or make the 2D ranch slower for baseline devices.

## Milestone order within each phase

1. Approve player goal and acceptance criteria.
2. Approve content/asset brief and cultural review needs.
3. Implement catalog + scene/UI behavior.
4. Integrate final asset/audio variants.
5. Run functional, accessibility, safety, and child-observation tests.
6. Fix priority findings before expanding scope.
